# Neural rendering and realism plan (2026-09-10)

Outcome of a research pass over the 2025-2026 state of the art in neural rendering,
checked against this repository's hard constraints (no build step, vendored single-file
libraries only, CC0 assets, degradable, WebGL2 baseline with optional WebGPU) and against
what the repo already contains (`js/neural_export.js`, the published terrain ControlNet,
`scripts/infer_server.py`, the offline bake in `maps/default/bake.jpg`).

The headline finding: nothing neural runs inside the game today, and no published
technique runs a realism network in a browser at interactive rates for an oblique-camera
low-poly RTS. The largest visible gains available now are rendering-pipeline fixes that
every neural approach assumes as a base (tone mapping, ambient occlusion) and the offline
neural bake for Mokra. The in-game neural pass is a medium-term project with the phases
and exit gates in section 2.

Status of the items in section 1 is tracked at the bottom of this file.

## 1. Ranked shortlist: implement NOW

Ranking criterion: visible gain for a 45 degree tilt orthographic camera where terrain fills most pixels, divided by risk to the no-build, CC0, degradable, WebGL2 constraints. Items 1 and 2 are pipeline fixes that every map benefits from; item 3 is the highest single-map gain and also produces the aligned teacher pairs the medium-term path needs; item 4 is conditional on item 1 settling.

| Rank | Item | Realism | Runtime cost | Effort | New vendored code |
|---|---|---|---|---|---|
| 1 | Filmic tone mapping (AgX) before the grade pass, exposure moved ahead of the curve | medium (fixes widespread clipping) | < 0.1 ms | hours + tuning session | none |
| 2 | N8AO screen-space AO (standard modes, half-res) plus view-fitted shadow frustum | medium (contact shadows) | 1.5 to 5 ms, measure | 2 to 3 days | 2 files |
| 3 | MPS port of `infer_server.py`, bake Mokra, bake provenance and memory guard | high for Mokra, zero elsewhere | 0 ms | 2 to 3 days (mostly compute) | none in browser |
| 4 | Data-fitted static 3D LUT after VALOR (conditional on 1) | low to medium | ~0.05 ms | 1 to 3 days | none |

### 1.1 Filmic tone mapping as a `ToneMappingEffect` (rank 1)

Why first: the frame is hard-clipped to LDR at the grade pass today. `HueSaturationEffect` ends with `min(color, 1.0)`, VALOR's `uExposure` (1.31, `js/valor.js:75`) then multiplies already-clipped data. With sun 4.2 and ambient 1.95 on `MeshStandardMaterial`, any sunlit surface with linear albedo above about 0.56 exceeds 1.0 before bloom, so clipping affects large sunlit areas, not only glints. Setting `renderer.toneMapping` would do nothing: three r180 only applies it when rendering to the screen and pmndrs materials set `toneMapped: false`.

Steps:
1. `js/main.js`: add `ToneMappingEffect, ToneMappingMode` to the `postprocessing` import and to `Game.PostFX`. Fix the comment on line 27: postprocessing is Zlib, not MIT.
2. `js/engine.js` `Game.setupPostFX`: inside its own try/catch build `const tone = new PF.ToneMappingEffect({ mode: PF.ToneMappingMode.AGX })` and pass it FIRST in the grade pass: `new PF.EffectPass(Game.camera, tone, hueSat, brightContrast, vignette)`. It has no CONVOLUTION attribute, so it merges into the existing pass. Store as `Game.postfx.tone`. On failure fall back to the current three-effect pass (chain identical to today).
3. Exposure: `ToneMappingEffect` has no exposure option. Set `Game.renderer.toneMappingExposure = 1.31` (three's AgX, Neutral, ACES and Cineon functions multiply by that uniform) and set VALOR's `uExposure` default to 1.0 in `Game._valorDefaults`. Leave VALOR's aerial, chiaroscuro and sfumato on the tone-mapped data; they read `inputBuffer` after the grade pass either way.
4. Re-tune: bloom threshold (0.65 was chosen against clipped data), hue/saturation/brightness/contrast, VALOR grade defaults. Paste back from the copy-values box (`Game.postfxValuesText`).
5. Do not ship an external `.cube` file (asset rule). The optional LUT collapse of hueSat + brightContrast + VALOR grade into one `LUT3DEffect` is a design change (VALOR must be split into a pre-grade spatial effect and a post-grade grain effect), not a refactor; defer until the curve is settled, and if attempted bake with `LookupTexture` then `convertToUint8()`.

Libraries: none new. `ToneMappingEffect`, `ToneMappingMode`, `LUT3DEffect`, `LookupTexture`, `LUTCubeLoader` are already in `vendor/postprocessing-6.39.1.js` (Zlib, https://github.com/pmndrs/postprocessing/blob/main/LICENSE.md). AgX code in three r180 is MIT.

Degradation: constructor failure leaves the current chain; `Game.postFXDisabled` path untouched.

Debug panel (`Game._postfxControlDefs`): group `Tone`: select `toneMode` (LINEAR, ACES_FILMIC, AGX, NEUTRAL) applying `pf.tone.mode = ...`; slider `toneExposure` 0.3 to 2.0 applying `Game.renderer.toneMappingExposure`. Add both to `Game.postfxValuesText`.

Headless test (`scripts/postfx-tone-test.mjs`, modelled on `scripts/smoke-test.mjs`, server on :8741, never kill the user's server): boot, start mission, then in one `page.evaluate` call run `Game.renderScene()`, draw `Game.renderer.domElement` into a 64x36 2D canvas in the same task, read `getImageData`, return the fraction of pixels with all channels >= 254 and the mean. Assert: `Game.postfx.tone` exists, `mode === ToneMappingMode.AGX`, clipped-pixel fraction with AGX is lower than after setting `mode = LINEAR` (toggle through the control's `apply`), and no console errors other than optional 404s. If the WebGL context fails under headless Chromium, launch with `args: ['--enable-unsafe-swiftshader']`.

Neural note: `js/neural_export.js` renders `rgb` via `renderer.render` into a plain target and bypasses the composer, so this change does not alter neural inputs unless the exporter is changed (see 2.2).

### 1.2 N8AO ambient occlusion plus view-fitted shadow frustum (rank 2)

Why: the scene has flat `AmbientLight` and no contact darkening under vehicles, at wall bases, inside hedgerows and tree crowns. N8AO handles orthographic cameras in code (`camera.isOrthographicCamera` sets `#define ORTHO` for the AO and denoise passes; the compositer picks it up when configured through the proxy after construction). Realism is medium, not high: N8AO multiplies AO into lit colour, so it also darkens sunlit creases, and alpha-tested foliage produces noisy AO the denoiser must absorb.

Vendor (2 files, both permitted under the vendored-ESM rule):
- `vendor/n8ao-2.0.1.js` from https://cdn.jsdelivr.net/npm/n8ao@2.0.1/dist/N8AO.js (233 KB, published 2026-08-10). Licence: repo LICENSE is CC0 1.0 (https://raw.githubusercontent.com/N8python/n8ao/master/LICENSE); package.json says ISC. Record CC0 per LICENSE in `CREDITS.md`, note the discrepancy.
- `vendor/jsm/postprocessing/Pass.js` from https://cdn.jsdelivr.net/npm/three@0.180.0/examples/jsm/postprocessing/Pass.js (MIT). Needed because N8AO imports three bare specifiers: `three`, `postprocessing`, and `three/examples/jsm/postprocessing/Pass.js`; the importmap maps only `three/addons/`.

Steps:
1. `index.html` importmap: add `"n8ao": "./vendor/n8ao-2.0.1.js"` and `"three/examples/jsm/postprocessing/Pass.js": "./vendor/jsm/postprocessing/Pass.js"`.
2. `js/main.js`: `import { N8AOPostPass } from 'n8ao'`, add to `Game.PostFX`.
3. `js/engine.js` `setupPostFX`: in its own try/catch, immediately after `composer.addPass(new PF.RenderPass(...))` and before `smaaPass`: `const ao = new PF.N8AOPostPass(Game.scene, Game.camera, w, h)`; set via proxy `ao.configuration.screenSpaceRadius = true; aoRadius = 32 (px); distanceFalloff = 0.2; intensity = 2.5; halfRes = true` (set after construction so the half-res compositer compiles with ORTHO); `ao.setQualityMode('Medium')`; `ao.enabled = false` until measured; `composer.addPass(ao)`; `Game.postfx.ao = ao`. Keep `transparencyAware` false (it re-renders the scene). Composer `setSize` propagates.
4. Shadow frustum (minutes, no library): `sun.shadow.camera` is a fixed 200x200 unit box on a 2048 map (`js/engine.js:59-64`) while the sun follows the camera (`js/camera.js`). Fit the ortho shadow frustum to the visible extent each frame (half-height = `Game.camera` zoom times aspect margin) so texel density scales with zoom. Expose `shadowFit` bool in the Shadows group. Independent of N8AO and cheap; do it first.
5. `CREDITS.md`: n8ao (CC0 per LICENSE, https://github.com/N8python/n8ao) and three r180 `Pass.js` (MIT).

Degradation: try/catch around construction; `ao.enabled=false` leaves the chain identical; N8AO's `shouldUseNeuralDenoise()` self-disables neural modes with a console warning when its preconditions fail.

Debug panel: group `AO`: bool `aoEnable`, slider `aoIntensity` 0 to 6, slider `aoRadiusPx` 8 to 64, bool `aoHalfRes`, select `aoQuality` (Performance, Low, Medium, High, Ultra, Neural-Low, Neural-Medium, Neural-High), select `aoDisplay` (Combined, AO, Split), readout `aoMs` from `ao.enableDebugMode()` and `ao.lastTime` (uses `EXT_disjoint_timer_query_webgl2`).

Known risks to check in the real browser, not headless: open issue #53 (https://github.com/N8python/n8ao/issues/53) reports `glBlitFramebuffer` depth errors with multisampling 4 + halfRes on three 0.184; the game uses the same composer settings on r180, and VALOR already reads composer depth under MSAA without errors, so the non-halfRes path is exercised. The game renders at `min(devicePixelRatio, 2)` (`js/engine.js:18`), so a Retina 1440x900 window is 5.2 MP; neural modes force full resolution and are documented as not built for 4K, so keep them opt-in.

Headless test (`scripts/postfx-ao-test.mjs`): boot, enable AO through the control's `apply(true)`, run `Game.renderScene()` twice, assert no `console.error` containing `GL_INVALID` or `glBlitFramebuffer`; set `ao.setDisplayMode('AO')`, capture the canvas in the same task (as in 1.1), assert luminance variance above a small threshold (AO buffer is not uniform) and that the mean is below 250 (not blank white); repeat with `halfRes` on and off; disable and assert frame still renders. Timing numbers from SwiftShader are meaningless; only the error and image checks matter headlessly.

### 1.3 MPS port of `scripts/infer_server.py`, Mokra bake, bake hygiene (rank 3)

Why: the bake-once, ship-as-terrain-texture path already exists and is deployed for the default map (`maps/default/bake.jpg`, 8192x8192, 21.2 MB, commit 36fbbbf; loaded via `js/main.js:5719-5750`, `applyBakeImage` at 4468-4496; served via Bunny per `docs/CDN.md`). Mokra has no bake and is explicitly excluded at `js/main.js:5740`. This is the largest visible gain available for one scenario with zero runtime cost, and the ortho reference render versus bake pair is pixel-aligned, which is exactly what section 2 needs.

Steps:
1. `scripts/infer_server.py`: introduce `DEVICE = "mps" if torch.backends.mps.is_available() else ("cuda" if torch.cuda.is_available() else "cpu")`, replace the 10 CUDA-bound sites (lines 50, 72, 82, 111, 139, 180, 219, 257, 262, 335), use float16 with `variant="fp16"` on MPS (the diffusers-documented path; the bf16 default at line 43 is unverified end to end), map `torch.cuda.empty_cache` to `torch.mps.empty_cache`, batch size 1 on MPS behind a flag (diffusers warns MPS batch inference can fail).
2. Environment: `uv venv -p 3.12` with torch, diffusers (0.40.0 verified loading the checkpoint on this Mac), transformers, accelerate, safetensors, pillow, numpy. System Python 3.9.6 cannot host spandrel. Optional second iteration: spandrel (MIT) plus `models/RealESRGAN_x2plus.pth` from the Real-ESRGAN v0.2.1 release (BSD-3-Clause, https://github.com/xinntao/Real-ESRGAN).
3. First bake of Mokra at `steps=20, upscale=1, refine=0, detail=0` (about 50 min at the measured 14 s per 512 tile) to judge quality on the railway strip, which is out of the checkpoint's distribution (checkpoint 2026-07-05 predates the Mokra map and railway assets). Only then run the full chain (about 1.5 to 2 h on this Mac).
4. `js/main.js` boot: for `Game.currentScenario === 'mokra'` probe `maps/mokra/bake.jpg` with a `fetch(..., {method:'HEAD'})` and on success `await Game._applySavedMap({ name: 'mokra', _bakeUrl: 'maps/mokra/bake.jpg' })`; on 404 fall through to today's procedural look. `maps/*.jpg` is already in the Bunny `cdnPaths` rule.
5. Memory guard for both maps: produce a plain 4096 downscale of each bake (about 5 to 6 MB) and select it in `Game._applySavedMap` when `renderer.capabilities.maxTextureSize < 8192`, on mobile UAs, or via a debug toggle. The 8192 canvas upload costs about 341 MiB VRAM plus a 256 MiB CPU canvas, roughly 10x the `docs/texture.md` budget; keep 8192 on desktop because default zoom 20 at 1080p is 27 px per world unit and the 8192 bake matches that density.
6. `CREDITS.md`: add `maps/default/bake.jpg` and `maps/mokra/bake.jpg` as project-generated (SD1.5 ControlNet output, OpenRAIL-M Section 6 claims no rights in outputs; conditioning from the game's own render; training data CC0 on HF). Golden rule 2 is currently unmet for the default bake.

Degradation: HEAD 404 keeps today's look; 4096 fallback keeps low-VRAM devices booting.

Debug panel: group `Bake`: select `bakeResolution` (Auto, 8192, 4096, Off), readout of estimated terrain texture VRAM (`width*height*4*1.33`).

Headless test (`scripts/bake-load-test.mjs`): use `page.route('**/maps/mokra/bake.jpg', ...)` to serve the real file in one run and a 404 in another; start the Mokra scenario; assert `Game.terrainMesh.material.map.image.width === 8192` (or 4096 with the toggle) in the first run, a procedural `CanvasTexture` in the second, and no errors beyond the expected 404. Also run `node scripts/bunny-cdn-check.mjs` after sync.

Do not attempt the per-class tileable atlas variant or a KTX2 conversion at 8192 in this window (see section 4).

### 1.4 Data-fitted static 3D LUT applied after VALOR (rank 4, conditional)

Why: it replaces the hand-tuned hue-band grade in `js/valor.js:95-110` with a palette learned from the project's own 600 CC0 pairs, at the cost of one 3D texture fetch. Realism is low to medium: colour only, terrain-dominated. Fit it only after item 1 changes the tone curve, and fit it on frames captured with that curve.

Steps:
1. Data: pull https://huggingface.co/datasets/tstruk/under-fire-terrain-pairs (CC0, 600 pairs, 2.91 GB; local copies also exist under `~/Documents/render-terrain*`, counts only). Mask annotation-marker colours (purple, blue, red, pink), downsample both sides to about 128 px, and fit ONE 33^3 LUT with no CNN: Reinhard colour statistics transfer in Lab evaluated on the grid, or a least-squares fit with the Zeng smoothness (1e-4) and monotonicity (10) regularisers via `F.grid_sample` on CPU (3D `grid_sample` is not implemented on MPS). Write `assets/lut/terrain_grade.cube` (about 1 MB) or a 1089x33 PNG strip. The LUT is derived from CC0 data and non-copyrightable AI output; dedicate it CC0 in `CREDITS.md`.
2. `js/main.js`: add `LUT3DEffect, LookupTexture, LUTCubeLoader` to the import and `Game.PostFX`.
3. `js/valor.js` `Game.setupValor`: load with `LUTCubeLoader`, call `lut.convertToUint8()` (float LUTs with `LinearFilter` need `OES_texture_float_linear`, which is not core WebGL2; RGBA8 is filterable and gives the 144 KB figure), construct `new PF.LUT3DEffect(lut)` and merge it into the VALOR `EffectPass` after the grade uniforms, with `uGradeDesat 0, uGradeTemp 0, uFoliageSat 1, uMetalDesat 0` when the LUT is active. Training frames are full composer output (`Game.renderScene` runs the composer), so the LUT belongs at the end of the chain, not inside the mid-chain grade pass.
4. Only if the static LUT visibly helps, train the full Zeng image-adaptive model (Apache-2.0, https://github.com/HuiZeng/Image-Adaptive-3DLUT), bake mean weights into day, overcast and dusk LUTs and switch per scenario.

Degradation: load failure or missing file skips the effect and keeps the existing VALOR grade.

Debug panel: group `LUT`: bool `lutEnable`, slider `lutOpacity` 0 to 1 (`effect.blendMode.opacity`), select `lutFile` if several ship.

Headless test: route the `.cube` to a 404 in one run and assert VALOR still constructs and no errors; in the other run assert `Game.valor.lut` exists, `lut.type` is `UnsignedByteType`, and the same-task canvas mean colour shifts measurably when `lutOpacity` toggles 0 to 1.

## 2. Medium-term path: a true in-game neural pass

Target shape (all sweeps agree): RGB-only runtime, rich supervision offline, a static-shape 0.5 to 1M parameter UNet at 960x540, ONNX opset 17, onnxruntime-web WebGPU EP with GPU-buffer IO binding and graph capture, upscaled to display resolution, VALOR as the always-available fallback. Budget: 10 to 15 ms on mid-range discrete GPUs; integrated GPUs sustain only FSRCNN or Anime4K-class nets at 540p to 1080p; 1080p native inference of a 1 to 2M UNet is not interactive below a 4090.

### 2.2 Prerequisites checklist
- Item 1.3 delivered (aligned teacher pairs, MPS inference).
- Exporter defects fixed (fog leak, composer bypass, missing normals and albedo channels).
- Phase A numbers for Chrome, Safari 26.2 and Firefox recorded in `docs/neural-renderer/`.
- A written licence decision for student weights trained on gpt-image-2 outputs (OpenAI assigns Output to the user but prohibits using Output to develop competing models; not a copyright issue, a terms risk that attaches to the published ControlNet as well).

### 2.3 Risks
- Realism unproven for this regime: EPE, REGEN, HyPER-GAN and DLSS 5 refine already-detailed content; here the net must synthesise texture from semantics at tens of pixels per unit. Nothing published covers an oblique low-poly RTS.
- Cross-browser zero-copy does not exist: Firefox (all platforms) and shipping Safari 26.x do a CPU readback for canvas sources; Chromium forces readback on Linux and Windows OpenGL ES. WebKit's GPU path landed in WebKit main on 2026-09-09 and is not in Safari 26.2.
- ORT on Safari/WebKit 26 was still failing on 1.29.0 (issue #26827 re-reported 2026-09-02); Firefox pays about 1 ms per dispatch, so a 20 to 40 kernel net is 20 to 40 ms of overhead.
- The JSPI bundle hard-throws where `WebAssembly.Suspending` is absent; keep the asyncify bundle.
- Retina DPR 2 quadruples pixel counts; the neural path must force DPR 1 and 960x540 when active.
- Download size (about 26 MB raw) must remain lazy and optional; never enable COOP/COEP for wasm threads because it breaks the Draco CDN load.
- Selection rings and health bars are in-scene meshes; without the second UI pass they are baked into the network input.
- Single-frame inference on a panning camera will shimmer until phase F.

## 4. What NOT to do, and why

Pipeline
- Do not set `renderer.toneMapping` and expect a change: three r180 gates it on rendering to the screen and pmndrs materials set `toneMapped: false`. Use `ToneMappingEffect`.
- Do not append the tone mapper after the grade pass or inside VALOR: `HueSaturationEffect` clips to 1.0 first, so the curve would receive LDR data and roll off nothing.
- Do not hand `LUT3DEffect` a float `LookupTexture` with `LinearFilter`: RGBA32F filtering needs `OES_texture_float_linear` even in WebGL2 and samples black without it. Always `convertToUint8()`.
- Do not ship any third-party `.cube` film LUT: it is an asset under the CC0 rule. Bake procedurally or from the project's own CC0 pairs.
- Do not enable N8AO Neural-* modes by default: they force full resolution, the game renders at DPR 2 (5.2 MP on a Retina 1440x900 window), and the author states they are not built for 4K.
- Do not use `createImageBitmap(canvas)` as the handoff fallback: it is asynchronous, so it misses the same-task rule and hits the cleared drawing buffer it was meant to avoid. The fallbacks are `preserveDrawingBuffer: true` or skipping the neural path.
- Do not plan on zero-copy WebGL to WebGPU across browsers: only Chromium on macOS and Windows D3D takes the GPU mailbox path today.
- Do not enable COOP/COEP for wasm threads: it breaks the Draco decoder CDN load in `js/engine.js`. Run ORT with `numThreads=1`.
- Do not migrate to `WebGPURenderer`/TSL before a model is proven: pmndrs postprocessing v6 and VALOR are WebGL-only, realism-effects excludes orthographic cameras, and the migration would rewrite the whole finishing pass for no realism gain.
- Do not ship a 540p render plus FSR1 as the default: spatial upscaling destroys the thin features (infantry, gun barrels, hedgerow twigs, tracers) an oblique RTS depends on; keep `upscaleFactor` 1.0 for players. Do not copy the Shadertoy or Godot EASU ports (CC BY-NC-SA); write a fresh MIT-clean port if the path is ever used.

Neural runtime
- Do not adopt LiteRT.js as the plan of record: open unanswered WebGPU correctness bugs on the developer's exact hardware (M4 Max), whole-model wasm fallback without JSPI (Safari, flagged Firefox), no fp16, and a Linux-first converter with a known macOS ABI break. Keep the student export-agnostic and revisit by measurement.
- Do not treat DLSS 5, HyPER-GAN or REGEN figures as browser-achievable or design for a 4 to 8 ms budget: HyPER-GAN needs 12 to 30 ms natively on a 4070 Super, browser WebGPU is several times slower, and a net small enough to hit 8 ms at 0.5 Mpx has no published evidence of delivering realism. Budget 10 to 15 ms on discrete GPUs at 540p.
- Do not ship any neural runtime download at boot or without a WebGPU and UA gate; keep it lazy behind the debug panel until Chrome, Safari and Firefox numbers exist.
- Do not rely on Safari for ORT WebGPU until #26827 is re-tested on a fixed release; do not ship the JSPI bundle, which hard-throws without `WebAssembly.Suspending`.

Data and teachers
- Do not replace gpt-image-2 with FLUX.2 klein 4B without the bounded A/B: no structural conditioning, no guidance knob, 20 to 45 s per edit on this Mac, and REGEN's authors report colour drift and flicker from it. Team-coloured units cannot tolerate colour drift. Treat klein 9B as research-only (non-commercial licence).
- Do not regenerate the dataset or retrain the ControlNet for RenderFlow/FrameDiffuser-style 10-channel G-buffer conditioning on the Mac: no consumer exists, the models are 1 FPS or slower offline, and both are indoor or UE5-PBR trained with documented style drift.
- Do not build a HyPER-GAN or Pix2PixHD-class student on the 600 HF pairs alone: they are not pixel-aligned, contain no units, and were captured at tilt 35 while the game defaults to 45. Use them for colour and style losses only.

Offline assets
- Do not attempt the per-class tileable ControlNet atlas: single-class conditioning is out of distribution for the checkpoint, the seam blending is not circular tiling, and the terrain painter would need a rewrite from flat fills to atlas sampling.
- Do not convert the 8192 bake to KTX2 expecting to meet the `docs/texture.md` budget: UASTC transcodes to BC7 at about 85 MB with mips, ETC1S visibly degrades noisy terrain, `CompressedTexture` is not drawable so Bake View and map save break, and KTX2Loader is seven vendored files. Only a 4096 KTX2 (about 21 MB) fits, at half the density. Ship the plain 4096 JPEG fallback instead.
- Do not derive terrain PBR maps with Marigold or DeepBump: `textures/terrain_normal.jpg` and `terrain_ao.jpg` are dead files, the live normal map is `textures/oga/ground_detail_nrm.jpg`, roughness and AO are runtime canvases, the terrain shader clamps roughness to 0.38 so no map can produce glint, and the bundled Poly Haven and OGA sources already ship authored CC0 roughness/AO/displacement that a neural guess would replace with something worse.
- Do not use MatFuse: native 256x256, non-tileable by the authors' own statement, trained on Substance Share data, pinned to torch 1.13 CUDA.
- Do not apply StableMaterials sets to `fr_house_2.glb`, the dividers, the bridge or Sketchfab tanks: they are atlas-UV models needing Blender re-UV work (MODEL_PIPELINE), not a texture swap. Limit any material generation to procedural fallback walls, roofs, chimneys and rubble, and check visibility at zoom 16 to 20 before producing more than three to five sets.
